### **🔴 问题1：职业增益amplifier溢出导致游戏平衡破坏 (High优先级)**

#### **问题根因**
- 当前实现使用 `amplifier + 100` 作为职业效果的标记
- Bukkit将这个值解释为真实的药水等级，导致力量效果变成101级（+303伤害）
- 清除职业效果时会误删科技增益

#### **修复方案**
**文件**: `src/main/kotlin/cn/lcofficial/guozhan/manager/ProfessionManager.kt`

1. **新增独立存储机制**:
   ```kotlin
   // 🔧 v1.3.49: 修复职业amplifier溢出问题 - 使用独立存储跟踪职业效果
   private val playerProfessionEffects = ConcurrentHashMap<UUID, Set<PotionEffectType>>()
   ```

2. **重构applyProfessionEffectsSafe方法**:
   - 移除 `amplifier + 100` 标记机制
   - 使用原始amplifier值（0-3范围）
   - 记录职业效果到独立存储

3. **重构clearProfessionEffectsSafe方法**:
   - 使用独立存储跟踪职业效果
   - 通过TechEffectManager获取科技效果amplifier
   - 只清除职业效果，保留科技效果

4. **新增TechEffectManager.getTechEffectAmplifier()方法**:
   ```kotlin
   fun getTechEffectAmplifier(player: Player, effectType: PotionEffectType): Int
   ```

#### **修复效果**
- ✅ 职业效果amplifier恢复正常范围（0-3）
- ✅ 消除游戏平衡破坏问题
- ✅ 职业效果与科技效果完全分离
- ✅ 清除职业效果时不再误删科技增益

### **🔴 问题3：科技研究失败时资源永久扣除 (High优先级)**

#### **问题根因**
- `startResearch()` 方法在 `try { transaction { } } catch` 结构中
- 资源扣除、缓存更新在transaction外部执行
- 如果数据库写入失败，catch只记录日志和调用 `callback(false)`
- 导致金币/钻石永久扣除，但研究状态卡在"进行中"

#### **修复方案**
**文件**: `src/main/kotlin/cn/lcofficial/guozhan/manager/TechnologyManager.kt`

1. **将所有状态修改包装在单个transaction中**:
   ```kotlin
   // 🔧 v1.3.49: 在单个transaction中执行所有状态修改，确保原子性
   transaction {
       // 扣除资源
       country.diamond -= cost.diamond
       country.gold -= totalGoldCost
       
       // 验证资源充足性
       if (country.gold < 0 || country.diamond < 0) {
           throw IllegalStateException("资源不足")
       }
       
       // 保存国家资源变更
       country.save()
       
       // 更新缓存
       // 保存科技研究状态到数据库
   }
   ```

2. **增强错误处理**:
   - 详细的错误日志记录
   - 清理可能的缓存状态
   - transaction自动回滚确保数据一致性

#### **修复效果**
- ✅ 科技研究失败时资源自动回滚
- ✅ 缓存状态与数据库状态保持一致
- ✅ 消除资源永久扣除问题
- ✅ 研究状态不会卡在"进行中"

### **⚠️ 问题4：忠诚度批量保存丢失失败的领土 (Medium优先级)**

#### **问题根因**
- `LoyaltySystem.run()` 方法在批量保存时
- 即使某些领土的 `saveInTransaction()` 失败，仍然执行 `pendingSaveTerritories.clear()`
- 导致失败的领土被遗忘，忠诚度时间戳永远不会持久化

#### **修复方案**
**文件**: `src/main/kotlin/cn/lcofficial/guozhan/task/LoyaltySystem.kt`

**修复前**:
```kotlin
transaction {
    for (territory in territoriesToSave) {
        try {
            territory.saveInTransaction()
        } catch (e: Exception) {
            // 记录错误但继续
        }
    }
}
pendingSaveTerritories.clear() // 清空所有，包括失败的
```

**修复后**:
```kotlin
val savedTerritories = mutableSetOf<TerritoryBlock>()
for (territory in territoriesToSave) {
    try {
        transaction { territory.saveInTransaction() }
        savedTerritories.add(territory)
    } catch (e: Exception) {
        // 记录错误，保留在列表中重试
    }
}
// 🔧 v1.3.49: 只移除成功保存的领土，失败的领土保留在列表中下次重试
pendingSaveTerritories.removeAll(savedTerritories)
```

#### **修复效果**
- ✅ 失败的领土保留在待保存列表中
- ✅ 下次忠诚度检查时自动重试保存
- ✅ 忠诚度时间戳最终会被持久化
- ✅ 提高数据持久化可靠性
