# GuoZhan v1.3.48 Critical问题修复报告

## 📋 修复概述

本次修复解决了v1.3.47版本引入的两个Critical级别问题和数据完整性问题：

### 🔴 Critical问题1：战争权限修复导致核心保护失效 ✅ **已修复**

**问题描述**：
v1.3.47的战争权限修复（`canBypassTerritoryProtectionInWar`方法）导致玩家可以直接攻击敌国核心，同时核心保护玻璃被破坏后没有重新生成，核心血量也没有扣除。

**根本原因**：
在TerritoryListener中新增的战争权限检查绕过了CoreListener的核心保护逻辑。

**修复方案**：
修改`canBypassTerritoryProtectionInWar()`方法（TerritoryListener.kt 第56-91行），添加核心保护范围检查：
- 检查玩家是否在核心保护范围内（2.0格内）
- 如果在核心范围内，返回false确保CoreListener处理保护
- 添加详细的调试日志记录

**修复代码**：
```kotlin
// 🔧 v1.3.48: 关键修复 - 检查是否在核心保护范围内
val player = user.player
if (player != null) {
    val location = player.location
    val coreCountry = cn.lcofficial.guozhan.manager.CoreManager.findCoreCountry(location)
    if (coreCountry != null) {
        val coreLocation = coreCountry.getCoreLocation()
        if (coreLocation != null) {
            val distance = location.distance(coreLocation)
            // 在核心保护范围内（2格内），不允许战争权限绕过
            if (distance <= 2.0) {
                Guozhan.instance.logger.info("[战争权限] 玩家在核心保护范围内，战争权限不适用")
                return false
            }
        }
    }
}
```

### 🔴 Critical问题2：数据库完整性 - 数据丢失风险 ✅ **已修复**

**问题描述**：
当前异步保存模式存在严重的数据丢失风险：
- `TerritoryBlock.save()` 和 `User.save()` 使用异步保存
- `ClaimManager.activeClaims` 完全在内存中，服务器重启时丢失
- `LoyaltySystem` 批量保存存在一致性问题

**修复方案**：

#### 2.1 添加同步保存选项
- **TerritoryBlock.kt**: 修改`save()`方法支持`async: Boolean = true`参数
- **User.kt**: 修改`save()`方法支持`async: Boolean = true`参数
- 返回`Boolean`表示保存成功状态
- 创建`saveInTransaction()`内部方法供同步和异步保存共用

#### 2.2 修复关键业务逻辑
- **ClaimManager.kt**: 占领完成时使用同步保存`territory.save(async = false)`
- 添加保存失败检查和取消逻辑

#### 2.3 修复批量保存一致性
- **LoyaltySystem.kt**: 使用事务进行批量保存
- 创建领土列表副本再保存
- 只在事务成功后清空`pendingSaveTerritories`
- 添加失败计数和重试机制

#### 2.4 占领进度持久化 ⚠️ **部分完成**
- **ClaimProgress.kt**: 创建新的数据类和表用于持久化占领进度
- **ClaimManager.kt**: 集成占领进度持久化（进行中）
- **DataManager.kt**: 添加`ClaimProgresses`到数据库迁移
