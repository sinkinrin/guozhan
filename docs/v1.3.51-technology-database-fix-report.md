## 🔍 **问题分析**

### **🔴 核心问题：科技研发系统数据库错误**

#### **问题现象**
```
[SQLITE_ERROR] SQL error or missing database (foreign key mismatch - "gz_country_technologies" referencing "gz_technologies")
缺失表：main.gz_technologies_backup
失败的SQL操作：INSERT OR REPLACE INTO gz_country_technologies
错误发生位置：TechnologyManager.kt:827行的startResearch方法
```

#### **问题根因分析**
1. **表重建过程中断**：在`ensureTechnologyTablePrimaryKey()`方法执行过程中，如果发生异常或服务器重启，备份表`gz_technologies_backup`可能没有被正确删除
2. **外键约束检查失败**：SQLite在执行`INSERT OR REPLACE`时会检查外键约束，如果发现引用的主表结构不完整，会尝试查找备份表
3. **事务回滚不完整**：重建过程使用了`PRAGMA foreign_keys=off`，但如果异常发生，可能导致外键状态不一致
4. **异常处理缺陷**：重建过程中的异常没有得到妥善处理，导致孤立的备份表存在

#### **错误传播路径**
```
用户执行科技研发命令
    ↓
GuozhanCommand.handleTechCommand()
    ↓
TechnologyManager.startResearch()  // 🔴 错误发生点
    ↓
transaction {
    CountryTechnologies.replace { ... }  // 🔴 外键约束检查失败
}
    ↓
SQLite检查外键约束
    ↓
尝试查找 gz_technologies 表
    ↓
发现表结构异常，尝试查找备份表
    ↓
❌ gz_technologies_backup 不存在
```

### **1. 数据库健康检查系统**

**新增方法**: `performDatabaseHealthCheck()`
- 在科技管理器初始化时执行完整的数据库健康检查
- 清理孤立的备份表
- 验证表存在性和结构
- 验证外键约束状态

```kotlin
private fun performDatabaseHealthCheck() {
    try {
        Guozhan.instance.logger.info("🔧 [数据库健康检查] 开始检查科技系统数据库完整性...")
        
        // 1. 清理孤立的备份表
        cleanupOrphanedBackupTables()
        
        // 2. 验证表存在性和结构
        validateTableStructure()
        
        // 3. 验证外键约束
        validateForeignKeyConstraints()
        
        Guozhan.instance.logger.info("✅ [数据库健康检查] 科技系统数据库健康检查完成")
    } catch (e: Exception) {
        Guozhan.instance.logger.severe("❌ [数据库健康检查] 数据库健康检查失败，尝试自动修复: ${e.message}")
        attemptAutoRepair()
    }
}
```

### **2. 孤立备份表清理**

**新增方法**: `cleanupOrphanedBackupTables()`
- 检查并删除所有可能的备份表
- 包括 `gz_technologies_backup`、`gz_country_technologies_backup`、`gz_technologies_temp`

```kotlin
private fun cleanupOrphanedBackupTables() {
    transaction {
        val backupTables = listOf(
            "gz_technologies_backup",
            "gz_country_technologies_backup", 
            "gz_technologies_temp"
        )
        
        backupTables.forEach { tableName ->
            try {
                exec("DROP TABLE IF EXISTS $tableName")
                Guozhan.instance.logger.info("🔧 [清理备份表] 已清理备份表: $tableName")
            } catch (e: Exception) {
                Guozhan.instance.logger.warning("⚠️ [清理备份表] 清理备份表 $tableName 失败: ${e.message}")
            }
        }
    }
}
```

### **6. 安全表重建**

**改进方法**: `rebuildTechnologyTableSafely()`
- 使用时间戳创建唯一的临时表名，避免冲突
- 增强的错误处理和恢复机制
- 确保临时表在任何情况下都会被清理

```kotlin
private fun rebuildTechnologyTableSafely() {
    transaction {
        val tempTableName = "gz_technologies_temp_${System.currentTimeMillis()}"
        
        try {
            // 1. 清理任何可能存在的备份表
            execute("DROP TABLE IF EXISTS gz_technologies_backup")
            execute("DROP TABLE IF EXISTS $tempTableName")
            
            // 2. 关闭外键约束
            execute("PRAGMA foreign_keys=off")

            // 3. 创建临时表并复制数据
            execute("CREATE TABLE $tempTableName AS SELECT * FROM gz_technologies")
            
            // 4. 删除原表并重新创建
            execute("DROP TABLE gz_technologies")
            SchemaUtils.create(Technologies)
            
            // 5. 从临时表恢复数据
            execute("INSERT INTO gz_technologies (...) SELECT (...) FROM $tempTableName")
            
        } finally {
            // 6. 清理临时表并重新启用外键约束
            execute("DROP TABLE IF EXISTS $tempTableName")
            execute("PRAGMA foreign_keys=on")
        }
    }
}
```
