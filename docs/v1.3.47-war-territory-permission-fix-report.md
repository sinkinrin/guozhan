## 🔍 **问题分析**

### **问题现象**
在战争状态下，同一国家的不同玩家对敌国领土的权限不一致：
- **玩家1**: 可以正常在敌国领土放置和破坏方块（GM发动的战争）
- **玩家2**: 无法在敌国领土放置和破坏方块

### **根本原因**
通过代码分析发现问题在于 `TerritoryListener.kt` 中的权限检查逻辑：

1. **现有逻辑缺陷**: `canBypassCapitalProtection()` 方法只检查首都领土的战争权限
2. **权限检查顺序问题**: 如果首都权限检查失败，代码会继续执行后续的所有者权限检查
3. **缺少通用战争权限**: 没有针对所有领土类型的战争权限检查机制

### **代码位置**
- `src/main/kotlin/cn/lcofficial/guozhan/listener/TerritoryListener.kt`
- 影响方法: `onBlockPlace()`, `onBlockBreak()`, `onPlayerInteract()`

---

## 🔧 **修复方案**

### **核心修复策略**
新增通用战争权限检查方法，确保所有攻击方国家成员在战争状态下都有一致的权限。

### **修复详情**

#### **1. 新增通用战争权限检查方法**
```kotlin
// 🔧 v1.3.47: 新增战争权限检查方法，支持所有领土类型的战争权限
private fun canBypassTerritoryProtectionInWar(user: User, territory: TerritoryBlock?): Boolean {
    if (territory == null || !territory.isOwned()) return false
    val attackerCountry = user.country ?: return false
    val defenderCountry = territory.owner ?: return false
    if (attackerCountry.id == defenderCountry.id) return false
    
    // 检查是否处于战争状态
    val isAtWar = WarManager.isAtWar(attackerCountry, defenderCountry)
    
    // 🔧 v1.3.47: 添加详细的战争权限调试日志
    if (isAtWar) {
        Guozhan.instance.logger.info("[战争权限] 玩家 ${user.player?.name} (${attackerCountry.name}) 在战争中对 ${defenderCountry.name} 的领土有权限")
    }
    
    return isAtWar
}
```

#### **2. 修复onBlockBreak方法**
```kotlin
// 🔧 v1.3.47: 修复战争权限不一致问题 - 检查战争状态下的权限
if (canBypassTerritoryProtectionInWar(user, territory)) {
    player.sendMessage("§7[调试] 战争状态 - 允许破坏敌国领土")
    return
}
```

#### **3. 修复onBlockPlace方法**
```kotlin

    val placedType = event.blockPlaced.type

    }
    
    player.sendMessage("§7[调试] 战争状态 - 允许在敌国领土建造")
    return
}
```

#### **4. 修复onPlayerInteract方法**

    player.sendMessage("§7[调试] 战争状态 - 允许使用敌国容器")
