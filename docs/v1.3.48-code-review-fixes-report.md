### 🔴 **Critical级别问题**

#### **问题1：职业-科技药水效果冲突**
**文件**: `src/main/kotlin/cn/lcofficial/guozhan/manager/ProfessionManager.kt`

**问题根因**:
- 原逻辑：职业效果用amplifier 0-10，科技效果用amplifier 100+
- 实际情况：科技配置的amplifier为0/1，会被职业逻辑清除
- 导致玩家登录时科技增益被职业逻辑误删

**修复方案**:
```kotlin
// 🔧 v1.3.48: 修复Critical问题1 - 职业-科技药水效果冲突
// 科技效果使用原始amplifier（0-10），职业效果使用amplifier+100作为标记
if (existingEffect.duration == Int.MAX_VALUE && existingEffect.amplifier >= 100) {
    // 只移除职业效果（amplifier >= 100），保留科技效果（amplifier < 100）
    player.removePotionEffect(effectType)
}
```

**修复位置**:
- 第199-218行：清理逻辑修复
- 第230-238行：应用逻辑修复
- 第255-271行：移除逻辑修复

#### **问题2：税收时间戳持久化缺失**
**文件**: `src/main/kotlin/cn/lcofficial/guozhan/economy/TaxSystem.kt`

**问题根因**:
- `collectTax()` 方法只更新内存中的 `taxPolicies` 缓存
- 没有同步更新 `country.lastAutoTaxTime` 并保存到数据库
- 服务器重启后会按照旧时间戳重新累加税收

**修复方案**:
```kotlin
// 🔧 v1.3.48: 修复Critical问题2 - 税收时间戳持久化缺失
val currentTime = System.currentTimeMillis()
cn.lcofficial.guozhan.util.run {
    country.lastAutoTaxTime = currentTime
    country.save()
    logger.info("🔧 [税收系统] 已更新国家 ${country.name} 的收税时间戳到数据库")
}
```

**修复位置**: 第176-190行

### ⚡ **High级别问题**

#### **问题3：忠诚度恢复命令线程安全问题**
**文件**: `src/main/kotlin/cn/lcofficial/guozhan/command/GuozhanCommand.kt`

**问题根因**:
- `/u restore confirm` 命令在EntityScheduler线程中直接修改TerritoryBlock对象
- 可能与GlobalRegionScheduler上的忠诚度定时任务同时操作同一对象

**修复方案**:
```kotlin
// 🔧 v1.3.48: 修复High问题3 - 忠诚度恢复命令线程安全问题
cn.lcofficial.guozhan.util.run {
    damagedTerritories.forEach { territory ->
        territory.loyalty = 100
        territory.lastLoyaltyUpdateTime = currentTime
        territory.save()
        restoredCount++
    }
    
    // 在GlobalRegionScheduler中完成后，再回到EntityScheduler通知玩家
    sender.scheduler.run(cn.lcofficial.guozhan.Guozhan.instance, { _ ->
        sender.sendMessage("§a已恢复 $restoredCount 块领土的忠诚度")
    }, null)
}
```

**修复位置**: 第2735-2761行

#### **问题4：资源分配回调时机错误**
**文件**: `src/main/kotlin/cn/lcofficial/guozhan/manager/EconomyManager.kt`

**问题根因**:
- `distributeResources()` 在排入EntityScheduler后立即调用 `callback(true)`
- 后续背包写入失败也不会回传错误

**修复方案**:
```kotlin
// 🔧 v1.3.48: 修复High问题4 - 资源分配回调时机错误
try {
    // ... 背包操作
    callback(true)  // ✅ 成功后才调用
} catch (e: Exception) {
    // 🔧 v1.3.48: 背包操作失败时回调false
    callback(false)
}
```

**修复位置**: 第360-384行

---

#### **问题5：关闭服务器时的并发修改风险**
**文件**: `src/main/kotlin/cn/lcofficial/guozhan/task/LoyaltySystem.kt`

**问题根因**:
- `onDisable()` 中直接遍历 `pendingSaveTerritories`（普通MutableSet）
- 忠诚度任务可能仍在GlobalRegionScheduler中添加元素

**修复方案**:
```kotlin
// 🔧 v1.3.48: 修复High问题5 - 使用线程安全集合避免并发修改风险
internal val pendingSaveTerritories = Collections.newSetFromMap(ConcurrentHashMap<TerritoryBlock, Boolean>())
```

**修复位置**: 第29-31行，添加import第12行

### 🟡 **Medium级别问题**

#### **问题6：护盾系统成员查询回退错误**
**文件**: `src/main/kotlin/cn/lcofficial/guozhan/manager/ShieldManager.kt`

**问题根因**:

- 在Exposed中永远匹配不到（countryId是UUID类型）

```kotlin
// 🔧 v1.3.48: 修复Medium问题6 - 护盾系统成员查询回退错误
try {
    CountryManager.refreshMemberCache(country.id)

}
```

**修复位置**: 第549-560行
